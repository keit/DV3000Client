Getting Started

Install DV3K Client, connect your ThumbDV, then fill in your callsign and network details.

1. Install

Download the .deb or the AppImage for your computer: a PC (x86_64) with Debian 12, Ubuntu 24.04 or newer, or a Raspberry Pi 3 or later with the 64-bit Raspberry Pi OS with desktop.

.deb package

cd ~/Downloads
sudo apt install ./dv3kclient_*.deb

apt may print "Download is performed unsandboxed as root…". That's harmless: apt can't read your home folder as its own unprivileged user, so it reads the file as root instead. DV3K Client then appears in your app launcher, or run dv3kclient from a terminal.

AppImage

chmod +x DV3KClient-*.AppImage
./DV3KClient-*.AppImage

The AppImage (x86_64 for a PC, aarch64 for a Raspberry Pi) runs from wherever you keep it and doesn't add itself to the app launcher.

Your settings and log live in ~/.config/DV3000Client, shared by both, and are kept if you remove the app (sudo apt remove dv3kclient, or delete the AppImage).

2. Connect your ThumbDV

Follow the section for where your ThumbDV is plugged in:

Your ThumbDV is…One-time setup
A. Plugged into this PC Serial port access on this PC.
B. On a Raspberry Pi running AMBEServer On the Pi: AMBEServer and the latency udev rule. On Wi-Fi: power saving off on both machines.
C. Plugged into a Raspberry Pi running DV3K Client Serial port access on the Pi, as in A.

A. ThumbDV plugged into this PC

  1. Give yourself access to serial ports, then log out and back in:

    sudo usermod -aG dialout "$USER"

  2. In DV3K Client, open File › Settings › Devices, set ThumbDV to Local serial device and pick the device. Its stable name looks like /dev/serial/by-id/usb-NW_Digital_Radio_…_ThumbDV_…-if00-port0. To list what's plugged in:

    ls -l /dev/serial/by-id

DV3K Client sets the ThumbDV's latency timer to 1 ms itself each time it connects. In the rare case it can't, it shows a yellow warning above the tabs. Only then do you need the udev rule below.

B. ThumbDV on a Raspberry Pi running AMBEServer

The Pi runs PA7LIM's AMBEServer 3000, which makes the ThumbDV available over the network.

On the Pi:

  • Install and start AMBEServer 3000, following PA7LIM's instructions.
  • Add the latency udev rule. DV3K Client can't set the latency timer for you here, because the ThumbDV is opened by AMBEServer, not by DV3K Client.
  • On a Pi 3B+, the ThumbDV's USB link occasionally stalls, and AMBEServer stops answering until it's restarted. The AMBEServer watchdog restarts it automatically.

On this PC: open File › Settings › Devices, set ThumbDV to Network (AMBEServer 3000), enter the Pi's host name or IP address and port 2460, and press Test.

Every 20 ms of audio is a round trip to the Pi, so a wired network is best. Only one client can use an AMBEServer at a time. On Wi-Fi, turn off power saving on both machines. On an Ubuntu PC, also stop background Wi-Fi scans.

Turn off Wi-Fi power saving

Power saving can hold packets for 100 ms or more when traffic starts after a pause, which is exactly what pressing PTT does.

Raspberry Pi (Raspberry Pi OS, Pi-Star):

echo 'ACTION=="add", SUBSYSTEM=="net", KERNEL=="wlan*", RUN+="/sbin/iw dev $env{INTERFACE} set power_save off"' \
  | sudo tee /etc/udev/rules.d/70-wifi-powersave-off.rules
sudo reboot

Ubuntu PC (NetworkManager):

printf '[connection]\nwifi.powersave = 2\n' \
  | sudo tee /etc/NetworkManager/conf.d/wifi-powersave-off.conf
sudo systemctl restart NetworkManager

Check with iw dev <interface> get power_save. iw dev lists the interface names.

Stop background Wi-Fi scans (Ubuntu PC on Wi-Fi)

Every few minutes the Wi-Fi card scans all channels, which takes it off your network for about 9 seconds and breaks up audio for 10–20 seconds. On a GNOME desktop two things trigger these scans, and both need turning off:

  1. Location Services (Settings › Privacy & Security). Features that use your location stop working, e.g. Night Light's automatic schedule.

    gsettings set org.gnome.system.location enabled false

  2. NetworkManager's roaming scan, which stops when the connection is locked to your access point. The PC then won't switch access points by itself, so skip this on a mesh network or a laptop that moves around. Replace MyWiFi with your connection's name from nmcli connection show:

    iw dev | grep Interface                 # e.g. wlp1s0
iw dev wlp1s0 link | head -1             # Connected to xx:xx:xx:xx:xx:xx
nmcli connection modify MyWiFi 802-11-wireless.bssid xx:xx:xx:xx:xx:xx
nmcli connection up MyWiFi

C. ThumbDV plugged into a Raspberry Pi running DV3K Client

DV3K Client runs on the Pi itself, on a Raspberry Pi 3 or later with the 64-bit Raspberry Pi OS with desktop (Pi-Star and Raspberry Pi OS Lite have no desktop to run it on). Install the arm64 .deb or the aarch64 AppImage, then set up the ThumbDV exactly as in A.

  • The Pi has no microphone input: use a USB headset or USB sound card, and pick it in File › Settings › Devices.
  • If the same Pi also runs AMBEServer, stop it first. Only one program can use the ThumbDV at a time.

FTDI latency timer

ThumbDV plugged into the computer running DV3K Client (A or C): you only need this if DV3K Client showed a yellow "ThumbDV latency timer is … ms" warning.
ThumbDV on an AMBEServer Pi: always do this, on the Pi.

The ThumbDV's FTDI USB chip buffers data for up to 16 ms by default, which causes choppy, delayed audio. This udev rule sets it to 1 ms whenever the dongle is plugged in:

echo 'ACTION=="add", SUBSYSTEM=="usb-serial", DRIVER=="ftdi_sio", ATTR{latency_timer}="1"' \
  | sudo tee /etc/udev/rules.d/99-ftdi-latency.rules
sudo udevadm control --reload-rules

Unplug and replug the ThumbDV, then check. It should print 1:

cat /sys/bus/usb-serial/devices/ttyUSB0/latency_timer

3. Settings and your first contact

Open File › Settings:

  • General: your callsign and D-Star module letter, and your DMR ID. For each DMR network you use, pick it in DMR network and enter its server and password:
    • BrandMeister: the Hotspot Security password you set in BrandMeister SelfCare, not your account password.
    • TGIF: the 16-digit Hotspot Security Key from your TGIF account's security page.
  • Devices: your microphone and speaker (use the Test buttons to check them), and the ThumbDV from step 2.

Then:

  • D-Star: pick a reflector and module, and click Connect.
  • DMR: pick the network, click Connect, then choose a talkgroup.
  • PTT to send (or the space bar) toggles transmit on and off.

To hear yourself back, use the Parrot: on BrandMeister, tick Private call and call 9990; on TGIF, make a group call to TG 9990.

Something not working?

  • The log is at ~/.config/DV3000Client/dv3000client.log (Help › Log File Location).
  • Choppy audio: check the latency timer, and with AMBEServer, Wi-Fi power saving and background scans.
  • Report problems on GitHub Issues, with the log attached.
