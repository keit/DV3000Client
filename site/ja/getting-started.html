はじめに

DV3K Client をインストールし、ThumbDV を接続してから、コールサインとネットワークの情報を設定します。

1. インストール

DV3K Client は PC(x86_64)では Debian 12、Ubuntu 24.04 以降、Raspberry Pi では Pi 3 以降と 64 ビット版の Raspberry Pi OS(デスクトップ付き)で動きます。インストール方法は次の3つです。

apt でインストール(おすすめ)

keit APT リポジトリを一度登録してからインストールします。新しいバージョンは通常のシステム更新で届きます。

sudo curl -fsSLo /usr/share/keyrings/keit.gpg https://keit.github.io/apt/keit.gpg
sudo curl -fsSLo /etc/apt/sources.list.d/keit.sources https://keit.github.io/apt/keit.sources
sudo apt update
sudo apt install dv3kclient

以前に .deb を手動でインストールしていた場合も、リポジトリを登録するだけで次のバージョンからはリポジトリ経由で更新されます。

.deb をダウンロードしてインストール

ダウンロードページから自分の機器用の .deb をダウンロードして、次を実行します:

cd ~/Downloads
sudo apt install ./dv3kclient_*.deb

apt が 「Download is performed unsandboxed as root…」 と表示することがありますが、問題ありません。apt は通常、権限の低い専用ユーザーでファイルを読み込みますが、そのユーザーはホームフォルダーを読めないため、代わりに root で読み込んだという意味です。インストール後はアプリケーションランチャーに DV3K Client が表示されます。ターミナルから dv3kclient で起動することもできます。

AppImage をダウンロードして使う

chmod +x DV3KClient-*.AppImage
./DV3KClient-*.AppImage

AppImage(PC は x86_64、Raspberry Pi は aarch64)は置いた場所からそのまま起動でき、アプリケーションランチャーには自動で追加されません。

設定とログは ~/.config/DV3000Client に保存され、.deb と AppImage で共通です。アプリを削除しても(sudo apt remove dv3kclient、または AppImage のファイルを削除)残ります。

2. ThumbDV の接続

ThumbDV をどこに接続しているかに応じて、該当する節に従ってください:

ThumbDV の接続先初回のみ必要な設定
A. この PC に直接接続 この PC でシリアルポートへのアクセス権を設定。
B. AMBEServer を動かす Raspberry Pi に接続 Pi に AMBEServer とレイテンシの udev ルールを設定。Wi-Fi の場合は両方の機器で省電力機能をオフ。
C. DV3K Client を動かす Raspberry Pi に接続 A と同じく、Pi でシリアルポートへのアクセス権を設定。

A. この PC に直接接続した ThumbDV

  1. シリアルポートへのアクセス権を自分に追加し、一度ログアウトしてから再度ログインしてください:

    sudo usermod -aG dialout "$USER"

  2. DV3K Client で File › Settings › Devices(ファイル › 設定 › デバイス)を開き、ThumbDV を Local serial device にしてデバイスを選びます。固定のデバイス名は /dev/serial/by-id/usb-NW_Digital_Radio_…_ThumbDV_…-if00-port0 のような形です。接続中のデバイスは次のコマンドで確認できます:

    ls -l /dev/serial/by-id

DV3K Client は接続のたびに ThumbDV のレイテンシタイマーを自分で 1 ms に設定します。まれにそれができなかった場合は、タブの上に黄色い警告が表示されます。下の udev ルールが必要なのは、その場合だけです。

B. AMBEServer を動かす Raspberry Pi に接続した ThumbDV

Pi では PA7LIM 氏の AMBEServer 3000 を動かし、ThumbDV をネットワーク経由で使えるようにします。

Pi での設定:

  • PA7LIM 氏の手順に従って AMBEServer 3000 をインストールし、起動します。
  • レイテンシの udev ルールを追加します。この構成では ThumbDV を開くのは DV3K Client ではなく AMBEServer なので、DV3K Client はレイテンシタイマーを設定できません。
  • Pi 3B+ では ThumbDV の USB 接続がときどきストールし、AMBEServer は再起動するまで応答しなくなります。AMBEServer ウォッチドッグを入れておくと自動で再起動します。

この PC での設定: File › Settings › Devices を開き、ThumbDV を Network (AMBEServer 3000) にします。Pi のホスト名または IP アドレスとポート 2460 を入力し、Test を押してください。

20 ms ごとの音声がそれぞれ Pi との往復通信になるため、有線ネットワークが最適です。AMBEServer に同時に接続できるクライアントは1つだけです。Wi-Fi の場合は両方の機器で省電力機能をオフにし、Ubuntu の PC ではバックグラウンドの Wi-Fi スキャンも止めてください。

Wi-Fi の省電力機能をオフにする

しばらく通信がなかった後に通信が始まると(PTT を押した瞬間がまさにこれです)、省電力機能がパケットを 100 ms 以上保留することがあります。

Raspberry Pi(Raspberry Pi OS、Pi-Star):

echo 'ACTION=="add", SUBSYSTEM=="net", KERNEL=="wlan*", RUN+="/sbin/iw dev $env{INTERFACE} set power_save off"' \
  | sudo tee /etc/udev/rules.d/70-wifi-powersave-off.rules
sudo reboot

Ubuntu の PC(NetworkManager):

printf '[connection]\nwifi.powersave = 2\n' \
  | sudo tee /etc/NetworkManager/conf.d/wifi-powersave-off.conf
sudo systemctl restart NetworkManager

状態は iw dev <インターフェース名> get power_save で確認できます(インターフェース名は iw dev で確認)。

バックグラウンドの Wi-Fi スキャンを止める(Wi-Fi 接続の Ubuntu PC)

Wi-Fi カードは数分おきに全チャンネルをスキャンし、その間約9秒間ネットワークから離れるため、10〜20秒ほど音声が途切れます。GNOME のデスクトップではこのスキャンを起こすものが2つあり、両方を止める必要があります:

  1. 位置情報サービス(設定 › プライバシーとセキュリティ)。位置情報を使う機能は使えなくなります(例: 夜間モードの自動スケジュール)。

    gsettings set org.gnome.system.location enabled false

  2. NetworkManager のローミング用スキャン。接続を現在のアクセスポイントに固定すると止まります。代わりに PC が自動で別のアクセスポイントに移らなくなるため、メッシュネットワークや持ち歩くノート PC では行わないでください。MyWiFi は nmcli connection show で確認した自分の接続名に置き換えてください:

    iw dev | grep Interface                 # 例: wlp1s0
iw dev wlp1s0 link | head -1             # Connected to xx:xx:xx:xx:xx:xx
nmcli connection modify MyWiFi 802-11-wireless.bssid xx:xx:xx:xx:xx:xx
nmcli connection up MyWiFi

C. DV3K Client を動かす Raspberry Pi に接続した ThumbDV

DV3K Client を Pi 自体で動かします。Raspberry Pi 3 以降と、64 ビット版の Raspberry Pi OS(デスクトップ付き)が必要です(Pi-Star や Raspberry Pi OS Lite にはデスクトップがないため動きません)。arm64 の .deb か aarch64 の AppImage をインストールし、ThumbDV は A と同じ手順で設定してください。

  • Pi にはマイク入力がないため、USB ヘッドセットか USB サウンドカードを使い、File › Settings › Devices で選んでください。
  • 同じ Pi で AMBEServer も動かしている場合は、先に停止してください。ThumbDV を同時に使えるプログラムは1つだけです。

FTDI レイテンシタイマー

ThumbDV を DV3K Client を動かす機器に直接接続している場合(A または C): DV3K Client が黄色い「ThumbDV latency timer is … ms」 の警告を表示したときだけ必要です。
ThumbDV を AMBEServer の Pi に接続している場合: 必ず Pi で設定してください。

ThumbDV の FTDI USB チップは、デフォルトでデータを最大 16 ms バッファリングするため、音声が途切れたり遅れたりします。次の udev ルールで、ドングルを接続するたびに 1 ms に設定されます:

echo 'ACTION=="add", SUBSYSTEM=="usb-serial", DRIVER=="ftdi_sio", ATTR{latency_timer}="1"' \
  | sudo tee /etc/udev/rules.d/99-ftdi-latency.rules
sudo udevadm control --reload-rules

ThumbDV を一度抜き差ししてから確認してください。1 と表示されれば OK です:

cat /sys/bus/usb-serial/devices/ttyUSB0/latency_timer

3. 設定と最初の交信

File › Settings(ファイル › 設定)を開きます:

  • General(一般): コールサイン、D-Star のモジュール文字、DMR ID。使う DMR ネットワークごとに、DMR network でネットワークを選び、サーバーとパスワードを入力します:
    • BrandMeister: BrandMeister の SelfCare で設定した Hotspot Security パスワード(アカウントのパスワードではありません)。
    • TGIF: TGIF アカウントのセキュリティページで生成される16桁の Hotspot Security Key。
  • Devices(デバイス): マイクとスピーカー(Test ボタンで確認できます)、および手順2の ThumbDV。

その後:

  • D-Star: リフレクターとモジュールを選び、Connect をクリックします。
  • DMR: ネットワークを選んで Connect をクリックし、トークグループを選びます。
  • PTT to send(またはスペースキー)で送信のオン・オフを切り替えます。

自分の声を確認するには Parrot を使います。BrandMeister では Private call にチェックを入れて 9990 を呼び出し、TGIF では TG 9990 へグループコールします。

うまく動かないときは

  • ログは ~/.config/DV3000Client/dv3000client.log にあります(Help › Log File Location でも確認できます)。
  • 音声が途切れる場合: レイテンシタイマー、AMBEServer の場合はWi-Fi の省電力機能とバックグラウンドスキャンを確認してください。
  • 問題は GitHub Issues に、ログを添えて報告してください。
